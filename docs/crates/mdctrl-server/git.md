## 1 职责与非职责

职责（`基线`：[架构 5.2](../../architecture.md#52-services) “读取文档相关的 Git 元数据”；[技术选型 9.3](../../techStack.md#93-git-元数据)）：

- 探测 Git 是否可用，以及工作区所在的仓库；
- 通过 `git` CLI 批量读取状态、提交历史与差异；
- 在启动、文件变化与分支切换后刷新元数据，交给 [history](history.md#6-git-元数据合并) 合并；
- 为 agent 上下文与 View 提供按需差异。

非职责：

- 任何 Git 写操作（提交、暂存、切换、合并、推送）；
- 文档写入：与 Git 操作分离，写入使用原子替换（`基线`）；
- 保存 Git 数据的权威副本：快照是派生数据，可随时重新读取。

当前状态：未实现；属于 MVP2 范围（为 `stale` 规则与 agent 上下文服务）。技术选型记录的核查环境为 Git 2.43.0，porcelain v2 可用（[技术选型 9.4](../../techStack.md#94-验证状态)），这是核查环境的事实，不是最低版本要求。

## 2 探测

启动时在后台执行（不阻塞 server 可服务）：

1. 查找 `git` 可执行文件；
2. 在工作区根执行仓库探测，得到仓库顶层目录与 Git 目录（支持 `.git` 为文件的情况，如 worktree 与子模块）；
3. 读取 Git 版本，与最低支持版本比较（最低版本待确定，GIT-1）；
4. 得到可用性状态，见 [§6](#6-git-不可用时的行为)。

工作区根与仓库顶层的关系：

| 关系 | 处理 |
| --- | --- |
| 相同 | 直接使用 |
| 工作区是仓库子目录 | 所有路径在工作区相对路径与仓库相对路径之间转换；只读取工作区范围内的文件 |
| 工作区包含多个仓库或子模块 | MVP 范围内只使用工作区根所在的仓库；子模块内文档没有 Git 元数据（GIT-2） |
| 不在仓库中 | 不可用 |

## 3 获取

### 3.1 读取内容

| 数据 | 获取方式（建议） | 频率 |
| --- | --- | --- |
| HEAD 指向 | 解析 HEAD 指向的完整引用名（如 `refs/heads/main`），或判定为 detached | 启动、[§4](#4-刷新) 的触发 |
| 解析后的 HEAD 提交 ID | 由 Git 解析 HEAD 得到的提交 ID | 启动、§4 的触发与周期校准 |
| 工作区状态 | porcelain v2 状态输出，NUL 分隔 | 启动、去抖后的文件变化 |
| 每个文档的最近提交、作者、提交时间 | 一次性遍历提交历史，按路径取第一次出现的提交；限定在工作区路径范围 | 启动、HEAD 提交 ID 或指向变化 |
| 文档差异 | 按需执行，限定单个路径 | agent 上下文、View 请求时 |

- 所有输出使用 NUL 分隔格式，避免路径引号转义与非 UTF-8 路径问题；
- “每个文档的最近提交”在大仓库中成本较高，需要设置遍历上限或时间预算，超出时只返回已得到的部分并标注（`待验证`：大仓库耗时）；
- 作者信息包含姓名与邮箱，属于个人数据：在本地展示与作为 agent 上下文时按配置决定是否包含邮箱（GIT-3），不写入日志。

### 3.2 调用安全

Git 在不可信仓库中运行时，仓库配置可能触发外部命令执行。调用规则（`建议`）：

- 以参数数组启动进程，不经过 shell；路径参数前加 `--` 分隔，防止以 `-` 开头的文件名被解释为选项；
- 使用 `--no-optional-locks`：[git(1)](https://git-scm.com/docs/git) 说明该选项表示不执行需要锁的可选操作（等价于把 `GIT_OPTIONAL_LOCKS` 设为 `0`），避免 mdctrl 的后台状态读取与用户自己的 Git 操作争抢 index 锁；
- 设置 `GIT_TERMINAL_PROMPT=0`：[git(1)](https://git-scm.com/docs/git) 说明该变量为 false 时不在终端提示（如 HTTP 认证），防止后台调用挂起；
- 覆盖 `core.fsmonitor=false`：[githooks(5)](https://git-scm.com/docs/githooks) 的 fsmonitor-watchman 一节说明 `core.fsmonitor` 设为 hook 路径时由 Git 调用该程序，仓库内配置可借此执行程序；读取状态时显式关闭；
- 只调用只读子命令；不调用会触发 hook 的写命令；
- 每次调用设置超时与输出大小上限，超时后终止进程；
- 遇到 Git 的仓库所有权检查（`safe.directory`）拒绝时，按“不可用”处理并给出诊断，不自动修改用户的 Git 配置。

以上三项 Git 行为于 2026-11-14 对照所附 git-scm.com 页面核对（页面对应当时的最新 Git 文档，最低版本上的可用性见 GIT-1）；其他仓库配置项（如 diff 外部驱动、textconv）是否在只读调用中触发，需要逐项验证并补充（`待验证`，GIT-4）。

## 4 刷新

`基线`：Git 可用时，在启动、文件变化与分支切换后刷新（[架构 6.3](../../architecture.md#63-文档历史)）。

**为什么不能只监听 HEAD 文件**（以下 Git 事实于 2026-11-14 对照所附官方文档核对）：

- 在普通分支上，`.git/HEAD` 是一个符号引用，内容形如 `ref: refs/heads/master`（[git-symbolic-ref](https://git-scm.com/docs/git-symbolic-ref)、[gitrepository-layout](https://git-scm.com/docs/gitrepository-layout)）。普通 commit 与 amend 更新的是分支引用，HEAD 文件内容不变，工作区正文也可能不变；
- detached HEAD 时，HEAD 直接记录一个提交（[gitrepository-layout](https://git-scm.com/docs/gitrepository-layout)）；
- 分支引用可以是 `$GIT_DIR/refs` 下的松散文件，也可以只存在于 `packed-refs` 中；松散文件缺失时才查找 `packed-refs`，更新分支总是写松散文件（[git-pack-refs](https://git-scm.com/docs/git-pack-refs)）；
- 仓库可以使用 `reftable` 引用存储格式（[git-init](https://git-scm.com/docs/git-init) 的 `--ref-format`），此时上述文件布局不适用；
- 在 linked worktree 中，HEAD 是每个 worktree 私有的，`refs/` 下的引用大多共享；Git 文档建议用 `git rev-parse --git-path` 求实际路径，而不是假设路径属于哪个目录（[git-worktree](https://git-scm.com/docs/git-worktree)、[git-rev-parse](https://git-scm.com/docs/git-rev-parse)）。

因此区分两件事：**HEAD 文件内容**（指向哪个引用，或 detached）与**解析后的 HEAD 提交 ID**。判断“是否需要刷新提交元数据”以“HEAD 指向 + 解析后的提交 ID”这一对值为准，文件监听只作为触发提示。

刷新触发（`建议`）：

| 触发 | 刷新内容 | 方式 |
| --- | --- | --- |
| 启动 | 全部 | 后台执行，完成后批量交给 history |
| 文档变化（去抖后） | 工作区状态；同时比较 HEAD 指向与提交 ID | 合并多次变化，间隔不小于阈值 |
| 引用变化提示 | 比较 HEAD 指向与提交 ID，变化则刷新提交元数据 | 监听用 `--git-path` 解析出的 HEAD 文件、当前分支的松散引用文件、`packed-refs`（仅 files 格式） |
| 周期校准 | 同上 | 按可配置间隔解析 HEAD 并比较（GIT-5）；监听不可用或使用 reftable 时是主要手段 |
| client 获得焦点 / 显式命令 | 同上或全部 | 由 client 触发 |

场景对照：

| 场景 | HEAD 文件 | 解析后提交 ID | 能发现变化的途径 |
| --- | --- | --- | --- |
| 普通 commit | 不变 | 变化 | 分支引用文件监听、周期校准 |
| amend | 不变 | 变化 | 同上（正文可能不变，不能依赖文档变化） |
| 切换分支 | 变化 | 通常变化 | HEAD 文件监听、文档变化、周期校准 |
| 切换到 detached HEAD / 在 detached 状态下提交 | 变化（记录提交 ID） | 变化 | HEAD 文件监听、周期校准 |
| reset / rebase | 视情况 | 变化 | 引用文件监听、周期校准 |
| linked worktree | 私有 HEAD 在共享 Git 目录下的 worktree 子目录 | — | 用 `--git-path` 解析出的路径监听；分支引用在共享目录 |
| 引用已打包且未再更新 | 不变 | 不变 | 无需刷新 |
| reftable 格式 | 布局不同 | — | 周期校准与其他触发 |

- 引用文件监听受平台监听行为影响，只作为提示；漏掉的变化由周期校准兜底；
- 提交 ID 未变而只是 HEAD 指向变化（如在同一提交上切换到另一个分支）时，只更新分支名，不重新遍历提交历史；
- 分支切换刷新仍是技术选型中的待微型验证项，回退为启动时全量校准（[技术选型 9.4](../../techStack.md#94-验证状态)）。

刷新任务互斥：同一时间只有一个 Git 刷新任务，新的触发在当前任务结束后合并执行一次。Git 不可用时以上触发全部不启动，降级规则见 [§6](#6-git-不可用时的行为)。

## 6 Git 不可用时的行为

| 状态 | 原因 | 行为 |
| --- | --- | --- |
| `available` | 正常 | 全部功能 |
| `not_installed` | 找不到 `git` | history 独立工作；状态查询显示原因；只提示一次 |
| `not_a_repository` | 工作区不在仓库中 | 同上 |
| `refused` | 仓库所有权检查拒绝等 | 同上，诊断中说明原因与用户可采取的操作 |
| `degraded` | 单次调用超时或失败 | 保留上一次快照并标注过期；下次触发重试 |
| `unsupported_version` | 版本低于最低要求 | 同 `not_installed` |

原则：

- Git 不可用**从不阻止**阅读、搜索、编辑与健康检查（`基线`，[架构 15](../../architecture.md#15-基本约束与安全)）；
- 可用性状态通过 server 状态查询暴露给 client，不作为错误中断请求；
- Git 从可用变为不可用（如运行中卸载）时，快照的处理见 HIS-4。

## 7 关键取舍

- **CLI 而非库**：沿用技术选型结论（Git CLI，回退为文档历史独立运行）；行为与用户的 Git 一致，无额外依赖；代价是进程启动成本与输出解析，需要批量化。
- **只读与安全覆盖**：降低在不可信仓库中运行的风险；代价是部分用户自定义的 Git 行为（如 fsmonitor 加速）在 mdctrl 中不生效。
- **按需差异**：避免预先计算大量 diff；代价是首次查看差异有延迟。

## 8 验证方法

| 项目 | 方法 |
| --- | --- |
| 探测 | 无 Git、非仓库、子目录工作区、worktree、子模块 |
| 批量读取 | 大仓库（数万提交）下最近提交遍历耗时与上限 |
| 安全 | 夹具仓库配置 `core.fsmonitor` 指向记录调用的脚本，验证不被执行；以 `-` 开头的文件名 |
| 引用变化 | 普通 commit、amend（正文不变）后最近提交、作者、提交时间被刷新；切换分支；进入与在 detached HEAD 下提交；linked worktree 中提交；执行 `git pack-refs --all` 后再提交；reftable 格式仓库；监听不可用时由周期校准发现 |
| 非 UTF-8 与 CJK 路径 | NUL 分隔输出解析 |
| 锁争用 | 用户执行 `git commit` 时后台刷新不导致 index 锁冲突 |

## 9 待确认事项

- **GIT-1**（`ylgd0915`）：最低支持的 Git 版本。需在微型验证中确认 porcelain v2 与所用选项的可用版本后确定。
- **GIT-2**（`ylgd0915`）：子模块内文档是否需要 Git 元数据。建议 MVP 范围不支持。
- **GIT-3**（三人）：作者邮箱是否展示、是否进入 agent 上下文（可能发送到远程 provider）。建议默认只用姓名。
- **GIT-4**（`ylgd0915`）：除 fsmonitor 外，需要显式关闭的仓库配置项清单（diff 外部驱动、textconv 等）。
- **GIT-5**（`ylgd0915`）：周期校准的默认间隔，以及是否在 TUI 获得焦点时额外校准；需在大仓库上测量解析 HEAD 的开销后确定。
